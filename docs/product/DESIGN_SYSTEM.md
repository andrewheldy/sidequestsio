# SideQuests Design System

## Purpose

This document defines the visual language, interaction principles, and design philosophy of SideQuests.

It exists to ensure every screen, component, animation, and interaction feels like part of a single product.

Consistency is more important than novelty.

---

# Brand Personality

SideQuests should feel:

- Adventurous
- Playful
- Modern
- Approachable
- Premium
- Curious
- Community-driven

The product should inspire exploration without feeling childish.

Think "your favorite travel app meets your favorite game."

---

# Design Principles

Every design decision should reinforce these principles.

## Exploration First

The interface should encourage users to discover places rather than simply browse lists.

Maps, imagery, and nearby recommendations should always feel inviting.

---

## Reward Progress

Users should constantly feel they are making progress.

Examples:

- XP animations
- Level indicators
- Progress bars
- Completion checkmarks
- Reward confirmations

Small moments of positive feedback are encouraged.

---

## Simplicity Wins

A new user should understand every screen without needing instructions.

Avoid unnecessary complexity.

If a feature requires explanation, simplify the feature.

---

## Mobile First

The primary experience is designed for phones.

Desktop should support the experience, not define it.

Every interaction should be comfortable with one-handed use.

---

## Real Places Matter

Businesses and destinations are the stars.

Large imagery should showcase real locations rather than interface elements.

Photography should feel authentic rather than stock-like whenever possible.

---

## Delight Without Distraction

Animations should celebrate achievements without slowing users down.

Motion should support usability, not become entertainment itself.

---

# Visual Identity

## Logo

The SideQuests wordmark should be the primary logo.

Use lowercase:

sidequests

Avoid unnecessary iconography unless needed for compact layouts.

---

## Color Philosophy

The interface should rely on a restrained color palette.

Use bright colors intentionally to communicate progression and rewards.

Most screens should feel clean and neutral.

Color should emphasize:

- XP
- Points
- Buttons
- Status
- Success
- Alerts

Not decoration.

---

## Typography

Typography should prioritize readability.

Hierarchy should be obvious.

Use:

Large headings

Medium section titles

Comfortable body copy

Clear labels

Avoid decorative fonts.

---

## Icons

Icons should be:

Simple

Recognizable

Consistent

Never use multiple icon styles throughout the application.

---

# Layout Principles

Whitespace is valuable.

Avoid crowded interfaces.

Users should immediately identify:

- Primary action
- Supporting information
- Navigation

Every screen should have a single obvious focus.

---

# Cards

Quest cards should contain:

- Hero image
- Quest title
- Difficulty
- XP reward
- Point reward
- Estimated time
- Distance

Cards should prioritize imagery over text.

---

# Buttons

Every screen should have one primary action.

Examples:

Start Quest

Scan QR

Complete Quest

Capture the Moment

Redeem Reward

Primary buttons should always stand out.

Avoid multiple competing call-to-actions.

---

# Navigation

Bottom navigation should remain consistent.

Recommended tabs:

Home

Map

Scan

Adventure Log

Profile

Navigation should never exceed five primary destinations.

---

# Quest Experience

The Quest page is the emotional center of the application.

Every quest should communicate:

What am I doing?

Why is it interesting?

What do I earn?

How do I complete it?

Users should never need to guess the next step.

---

# Imagery

Photography should emphasize:

Real businesses

Food

Architecture

Neighborhoods

Events

People enjoying experiences

Avoid generic stock imagery whenever possible.

---

# Reward Experience

Completing a quest should feel satisfying.

Completion sequence:

Success confirmation

XP animation

Points animation

Reward information

Optional sharing

Community Note prompt

Adventure Log update

Each step should reinforce accomplishment without becoming repetitive.

---

# Empty States

Every empty screen should encourage exploration.

Examples:

"No quests completed yet."

"Start your first adventure."

"Explore nearby."

Never display blank pages without guidance.

---

# Error States

Errors should be:

Friendly

Actionable

Brief

Always explain what the user can do next.

Avoid technical language.

---

# Accessibility

The product should support:

- High color contrast
- Readable typography
- Large tap targets
- Screen readers where practical
- Keyboard navigation for web

Accessibility is a baseline requirement, not an enhancement.

---

# Performance

The interface should feel fast.

Prioritize:

Fast loading

Responsive interactions

Smooth scrolling

Quick transitions

Slow interfaces reduce the feeling of exploration.

---

# Design North Star

Every screen should answer three questions immediately:

1. Where am I?

2. What can I do here?

3. Why is this interesting?

If a screen fails to answer these questions, it should be redesigned.

---

# Experience Statement

SideQuests should make discovering the real world feel as exciting as unlocking a new area in a great game.

The interface exists to support that feeling—not compete with it.
